# v0.2.0｜恢复维护与 Rename

日期：2026-08-15

状态：维护中

仓库：`boss-recruiting-auto`

## 这次迭代解决什么

2026-08-06，项目因筛选命中率波动和 Token 成本被标记为 deprecated，README 同时声明仓库仅作历史存档。这个判断准确记录了当时不再把 Computer Use 全自动 Sourcing 作为日常默认方案的原因，但把“暂停一种使用方式”扩大成了“整个项目已失去维护价值”。

实际上，弃用提交只修改了 README。岗位画像、筛选标准、只读委派、页面执行、日志校验、测试和分发包都仍然存在。v0.2.0 因而不回滚历史，而是修正当前项目状态：恢复维护这套有边界的自动招聘工作流，同时保留此前暴露出的成本与准确性问题。

## 一直保留的核心资产

### 岗位画像：`hr-job-profile-library`

画像 Skill 仍然管理完整的岗位知识链：

- `jd.md`：岗位职责与要求；
- `persona.md`：核心人才特征、经验与能力画像；
- `screening-criteria.md`：硬性条件、加分项、排除项与证据要求；
- `business-feedback.md`：匿名业务反馈及证据等级；
- `job.json`、`changelog.md` 与历史快照：岗位标识、版本和变更轨迹。

岗位库支持创建、预览、应用、更新、解析和归档。下游操作 Skill 只能读取精确匹配的启用岗位，不得借委派修改岗位，也不得把候选人身份数据写回岗位库。

### 页面操作：`boss-zhipin-greeter`

操作 Skill 仍然提供一次完整、可中断、可审计的执行闭环：

1. 读取并冻结一个岗位版本及四份筛选上下文；
2. 使用 Computer Use 核验当前 BOSS 标签页、登录态、页面和岗位；
3. 在限定滚动次数内只读提取可见候选人；
4. 将规范化数据交给 Codex screening subagent 判断；
5. 逐人通过 Command-F 定位，核验同一卡片后点击默认“打招呼”；
6. 为提取、筛选、点击结果和停止原因留下结构化日志。

这两套 Skill 是同一个系统的两半：画像 Skill 约束判断依据，操作 Skill 约束页面行动。

## 为什么改名

旧名称 `boss-auto-greeter-system` 把项目重心压缩成“自动打招呼”，容易让人忽略此前最重要的判断链：岗位画像加载、候选人证据提取和筛选。

新名称 `boss-recruiting-auto` 保留 `BOSS` 与 `auto`，同时把范围提升到招聘自动化闭环。它表达的是：

- 项目面向 BOSS 招聘场景；
- 自动化覆盖画像读取、页面提取、筛选交接、定位触达和日志；
- “自动”仍受单轮授权、数量上限和停止条件约束。

本次只重命名仓库，不重命名两个 Skill。`$hr-job-profile-library`、`$boss-zhipin-greeter`、目录名、依赖声明和 `.skill` 包名都保持稳定，已有安装无需迁移命令。

## 如何理解“恢复维护”

恢复维护不是把之前的风险判断作废，也不意味着系统已经适合无人值守运行。

当前定位是“显式触发的 bounded automation”：用户授权一轮，系统只在冻结的岗位标准和候选人数上限内执行；证据不足、岗位歧义、验证码、登录失效、风控或页面不稳定时停止。运行结束后不会自动开启下一轮。

半自动工具仍可以作为并行方案存在。选择全自动或半自动，应取决于当前岗位、候选池、平台状态和人工复核成本，而不是由仓库是否存在来替代判断。

## v0.2.0 的兼容边界

本次没有修改：

- 岗位数据结构和版本规则；
- 岗位库到操作 Skill 的只读委派协议；
- Codex screening subagent 的职责；
- Computer Use-only 的页面操作约束；
- `scroll_count=3—5` 与 `candidate_limit=1—8`；
- 只发送 BOSS 默认招呼语；
- 运行日志字段与完成态校验；
- 公开仓库的隐私清理标准。

因此 v0.2.0 是项目定位、仓库命名和文档治理迭代，不是执行算法升级。

## 后续迭代的证据门槛

后续若要扩大自动化范围，应先积累可比较的运行数据，至少记录：

- 各岗位的筛选准确率、误触达数和人工复核差异；
- 单轮候选人数、完成率、平均耗时与 Token 成本；
- `not_found`、页面加载失败、登录/验证码/风控等中断原因；
- 岗位画像版本变化对筛选结果的影响；
- Computer Use 页面定位与点击确认的稳定性。

只有当准确率、成本和平台风险都有可复核的改善时，才考虑扩大单轮规模、减少人工检查或增加新的自动执行入口。否则保持现有边界。

## 验证基线

恢复维护前后的完成标准一致：

- `hr-job-profile-library`：32 项测试通过；
- `boss-zhipin-greeter`：14 项测试通过；
- `boss-zhipin-greeter` 契约校验通过；
- 两个 Skill 目录和两个 `.skill` 分发包保持存在；
- 仓库不包含真实组织、岗位、候选人、运行日志、凭据或本机绝对路径。
